# Default native optimizer activation

Bun and Worker default registry assembly now installs `createRegistryOptimization` when code mode, a sandbox transport, the selected model route credential and the account model ledger are available. A custom `RegistryHostFactory` still replaces defaults. Readiness reports `experiments`, `optimizationReason` and the effective `optimizationPolicy`; missing model accounting/transport does not install a model substitute. A custom experiment binding without the exact native trial adapter is unavailable and its runnable experiment tools/controller are omitted; a metadata-only deadline lifecycle remains mounted. The start-tool description also carries the current host bounds, including permitted built-in contracts and file surfaces. The generic standalone schema does not grant its larger maxima.

The binding retains the exact registry library object. `authorizeEvaluation` grants only host-owned fixed contracts/cases with the declared read effect and no dependencies; current configured management definitions retain their separate exact-artifact preflight grant. Optimizer authorization is narrower: built-in stateless JavaScript contracts only. Candidate source cannot replace cases, checkers, effects, model credentials or sandbox authority.

A native component counts three distinct checked ordinary executions after the current stable head. Fixture/acquisition/trial runs do not count. It starts at most one experiment for that stable generation with two repeats, one candidate, at most four fixed-case sweeps (baseline/candidate, development/held-out), 120 seconds, 1,024 proposal tokens and a $0.10 observed-cost limit. Physical inference is one request per retained proposal under the same conversation ledger. Unknown dollar measurements remain unknown; this is not a provider price guarantee. No guessed trial price ceiling is supplied. The account daily call allowance independently limits spend opportunities. Reflection receives development evidence only. A null candidate or empty hypothesis records `no-hypothesis` and immediately retains the baseline with reason `no-supported-hypothesis`, before opening held-out cases. Recovery preserves that stop without another proposal or trial. A proposed candidate still follows the fixed comparison and promotion rules.

Bun passes its existing SQLite `ModelBudget` object to conversation and reflection. Worker now uses one owner WorkflowKV atomic daily ledger for conversation, background and reflection; reservations precede transport and are never refunded after uncertain I/O. Worker accounts default to 40 physical calls/day, with bounded request/output size. This account-local ledger does not claim a cross-account global cap.

Parent actors mount the experiment controller, trigger and `trials.component()`. Native `harness-trial-*` children mount a worker-only actor with no conversation tools or usable inference. The dispatcher selects the owner from retained native parent lineage, so cancellation-only children run and a first foreign Work cannot select or poison the binding. The worker reconstructs a child-thread sandbox binding from the trusted closure, verifies its private brief and native parent link, and joins the actual child's checked witness. Bun persists children in its private `harness-trials` directory; its native host owns creation/lineage and the worker enforces the retained parent claim. Worker additionally gates `allowChild` to the owner foreground root and resolves all trial reads through the account host's `rootThread`. Public `AikoHarness*` input remains denied. Existing native cancellation/deadline routing supplies wakeups; there is no new scheduler.

`registry-optimization.test.ts` drives actual `createService` admission/code mode, acquisition, three ordinary jobs, native child trials, controlled real Infer wire, terminal baseline selection and disk reopen. It also exercises cancellation, owner credential revocation/restoration and unconfirmed dispatch without replay. The wire is a local fixture, not a live provider call. `registry-model-budget.test.ts` checks atomic retained spend, cross-instance reuse and tenant denial. `registry-worker-host.test.ts` bundles the actual Worker entry and constructs its real account/registry Durable Objects over on-disk SQLite platform storage. It uses the default registry factory, native code mode, real Infer wire adapter, real local sandbox jobs and fixed checkers. Its no-candidate fixture demonstrates four checked development child threads, exactly one reflection request, and baseline retention with `no-supported-hypothesis`; held-out cases remain unopened. It also verifies shared foreground/background/reflection ledger accounting and storage reopen with no repeated jobs or model requests. Full native trace and SQLite/WAL scans exclude private runtime input, held-out fixture text and provider credentials. Foreign admission, current-policy readiness, in-flight owner cancellation after execution-policy revocation, and missing transport are negative cases. No actor/controller/checker/result is replaced. The platform is a controlled SQLite adapter, not a deployed workerd or provider witness.

Worker application assembly can supply `AIKO_REGISTRY_SANDBOX(owner, ownerKV)` and `AIKO_MODEL_FETCH` as trusted transport dependencies. These function bindings are not HTTP inputs or JSON secret configuration. Omitting them preserves ordinary Codegraff selection. Supplying a sandbox factory that returns undefined means unavailable, not fallback. The physical edge fixture traps every other network call.

Authenticated owners can read `GET /api/harness/experiments/{id}/status` and stop retained work through `POST /api/harness/experiments/{id}/cancel`. The existing account principal and write scope gate cancellation before exact registered owner/experiment metadata is checked. Cancellation does not require execution/model authority, an unexpired deadline or a code segment; it appends only the native cancellation fact and arms the existing host wake path. Foreign or missing registrations cannot cancel. No library or private brief is required by these owner APIs. Current execution regime changes separately make optimizer readiness unavailable. `registry-optimization-policy.test.ts` covers expired/revoked cancellation authority and an actual native cancellation-only child with a poisoned first Work and no execution across restart.


Cold recovery is assembled independently of registry, code mode, model secrets and sandbox transport. Both production hosts always pass `harnessExperimentTrialLifecycle({owner,parentThread: "user-" + owner,readParent})` to the owner actor and provide its worker as `registryTrialActor`'s fallback. Native lineage selects the owner; an unavailable execution binding is never synthesized. Worker child admission still requires the native host's exact retained `ChildCreated` call ID and lineage. Its additional host gate permits owner-root trial lifecycle routing while code mode is disabled, including a retained edge whose first delivery is cancellation. It does not admit arbitrary children or authorize new execution.

The Worker cold-recovery fixtures capture actual SQLite state after retained ChildCreated before delivery, at native Work commit, and at physical job dispatch after RunStarted, before any Checked receipt. They restore those unmodified snapshots into a fresh production account object with code mode/model secret disabled or transport missing, delete all harness custody blobs/keys, and trap private reads. Owner cancellation delivers through the retained edge even before initial Work admission and returns an unavailable child for both unstarted cuts; a real alarm returns unknown for Started-without-Checked. No checked result is fabricated. All three cuts reach a native terminal and survive another reopen with zero jobs, model calls or private reads. Foreign credentials and unknown registration IDs are denied. Missing model credentials permit lifecycle boot and readiness/control APIs, while inference itself has an explicit unavailable layer. Execution routes retain their normal configuration checks.
