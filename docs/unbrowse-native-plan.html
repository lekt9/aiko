01 / DIRECTION

Keep the raise about Unbrowse.

The company story

“Unbrowse makes existing apps usable by agents: durable authentication, controlled execution, and reusable tools learned from successful work.”

Lead with completion rate, session continuity, repeatability, and cost per successful task. Speed remains a benefit, but “one second instead of ten” is not the whole business.

The consumer experience: Aiko

Aiko is the assistant’s name, not a second company or fundraising story. A capable assistant in Telegram that works with the apps someone already uses. The app drawer makes access tangible; chat makes outcomes easy to request.

Use this as Unbrowse’s first-party proving ground. Keep side-project names, marketplace ambitions, and unrelated experiments out of the fundraising narrative unless they earn exceptional traction.

The defensibility hypothesis: owning the consented execution loop lets Unbrowse improve authentication recovery, collect reliable outcome evidence, and turn recurring tasks into tested tools. Logs alone are not a moat; neither are cookies, credentials, or private customer data.

Focus: a small, invited cohort of mobile-heavy founders/operators, initially in Singapore if that is the intended launch market. Start with two consented app integrations and three narrow outcomes. Proposed candidates: GitHub issue triage and calendar agenda/draft-event workflows. Not in the first release: a tool marketplace, arbitrary third-party agents, general payments, bank access, autonomous purchases, WhatsApp/iMessage, voice calls, fine-tuning, or a universal “works with every login” promise. Expand Telegram text first; add voice only after delivery and permission semantics work.

Proposed side-project disclosure gate—not an existing result: eight consecutive weeks of retained, repeated use, positive contribution economics, and clearly attributable acquisition. Agree the numeric user/revenue threshold with the team before pitching an experiment as a second business. Competitor notes in the sketch are hypotheses, not verified market evidence.

02 / MOBILE PRODUCT

Make access look like apps,
not a password database.

The current mobile preview is already narrow-screen compatible, but its main object is a login: “All logins,” usernames, passwords, and “Add login.” Change the information architecture, not just the CSS.

  • Home = Your apps. Familiar icons, app names, account counts, and only actionable status. Search apps or accounts. Favorites first, then alphabetical.
  • Tap an app → its capabilities. “Summarize my issues” or “Check my calendar,” followed by connected accounts and access controls.
  • Accounts remain discoverable. Show Personal / Work, masked identity, sign-in method, and last checked time under “Accounts & access.” Login details are a secondary view, not removed.
  • Add app, not Add login. Select a supported service → choose an account → secure connection → verify identity → choose what the assistant may do.
  • App identity is not account identity. Two GitHub accounts form one app tile with an account picker. Never silently choose between Personal and Work for a write.
  • Four honest states: Ready, Needs you, Checking, Access paused. VM sleep does not make an app “disconnected.” Show “last checked” rather than claiming continuous verification.

Try the concept: search the drawer and tap an app. All account data is synthetic; controls do not connect anything.

Name: Aiko in Telegram, onboarding, app-drawer copy and user-facing messages. Unbrowse remains the company and execution infrastructure. Set the initial actor name deliberately when scaffolding; a display-name change must not rename existing actor instances or lose their histories. The persona is conversational text, not speech synthesis or a voice-call feature.

One voice, no second agent

The inspected SDK @curvelabs.org/thinkfeel@0.1.6 maps generate to POST https://playground.curvelabs.org/api/v1/generate with x-api-key and { personaId, messages, includeVariations }. Raw HTTP returns result.finalReply; the SDK flattens it to finalReply. personify uses POST /api/v1/personify with { personaId, raw }, returning personified and optional chunks. Neither endpoint was called here.

Production transport: the inspected SDK exposes no AbortSignal/timeout option and throws plain Error objects, not the sample’s guaranteed error.response. Implement the two documented HTTP calls in an application-owned, cancellation-aware Effect service so HTTP status, deadline, byte limits and retry headers remain available. Do not use a timeout race that leaves the original request running, and do not log raw provider error bodies.

Conversation validity: generate requires the last message to be from user; append the current user turn after prior assistant history. The pasted fan-greeting/booking-rejection example is mismatched fixture content, not Aiko’s history or an acceptable expected response.

  • Voice: warm, direct, concise and professional. Use Aiko’s name naturally, without forced intimacy or claims of being human. Confirm drafts versus completed actions explicitly.
  • Facts outrank persona: no added names, amounts, dates, accounts, urgency, promised escalations or completed actions. Prompt instructions and an LLM judge are not guarantees. Render consequential facts and approval cards deterministically outside the rewrite; discard uncertain or conflicting prose.
  • Durability: an application-owned aikoVoice component records a proposed speech intent keyed by tenant, reply ID, draft hash, persona ID and policy version. Persist accepted wording once; recovery reuses it instead of regenerating new phrasing. Keep task completion and message delivery separate. An ambiguous generation timeout can still incur duplicate billing; no provider idempotency is assumed.
  • Privacy: disclose Curve Labs as an additional text-processing service and confirm retention/training terms. Send only needed, redacted context; keep histories, caches and provider responses tenant-scoped. Private facts can remain sensitive even after credentials are stripped. Never send the whole Telegram transcript by default.
  • Bounded failure: propose a 5-second expression deadline, a short circuit-breaker and no more than one transient retry inside that total deadline. Handle 401/403/404/422 without retry; 429 may mean quota or insufficient balance. Use a shared key-level limiter across tenants. “25/Minute” in the sample is not a verified plan limit.
  • Safe fallback: ordinary generated replies go through ThinkFeel; deterministic acknowledgements, security notices and exact approval text may bypass it. On timeout, empty output or factual drift, use an approved Aiko template plus the verified receipt rather than block indefinitely or invent success. Do not claim fallback text came from ThinkFeel.
  • History: future conversational context contains the wording actually sent, not both GLM’s draft and the personified reply. Validate status where present and nonempty bounded text; do not blindly trust SDK casts or provider chunk lengths. Telegram chunking and escaping remain ours.
Activation gate: after the rotated secret is provisioned and a capped test is approved, run synthetic greeting, completed-read, draft-not-sent, failed-task and approval scenarios. Test wrong-name/persona leakage, the mismatched booking reply, altered amounts/dates, injected instructions, empty/malformed responses, cancellation, 429/outage fallback and replay after generation. 04 / TELEGRAM INGRESS

Native channel. Durable delivery.

The pinned upstream implements telegram({ name, token, secretToken, target, method }) in packages/channels/src/providers/telegram.ts, re-exported by its Telegram entry point. It verifies the webhook secret, maps text updates into MessageReceived with telegram:{update_id} IDs and replies with sendMessage.

It is text-first, not a finished consumer bot. The inspected adapter does not implement callback queries, media, message editing, approval buttons, Mini App identity verification or full outbound delivery reconciliation. Extend the native provider/host boundary with tested handlers; do not build a competing conversation loop.
  • Private chats only for v1. Reject groups before routing. Bind the verified numeric from.id to an internal user ID; never use username, display name or arbitrary client-supplied tenant/VM ID as authority. Treat the chat ID as a delivery address.
  • Ingress: bound body size, validate secret header, persist an inbox record keyed by bot + update ID, then return 200. Dispatch through the native channel. Per-user serialization plus per-account locks prevent two commands or a human and agent racing.
  • Mini App: validate signed initData server-side, expiry and replay policy; issue a short-lived application session. Never trust initDataUnsafe. Link an existing Unlock owner identity with an authenticated, one-time, explicit flow.
  • Approval: bind user, task, account, exact argument digest, contract version and expiry to a single-use nonce. Verify callbacks server-side and re-check grants just before execution. “Yes” alone is ambiguous with multiple pending tasks.
  • Replies: maintain an outbox, Telegram message IDs where available, rate-limit/backoff and 4096-character chunking. Telegram sends have an ambiguous-response duplicate window; do not claim exactly-once delivery. Use stable status-message edits once an ID is known.
  • Commands: /start, /apps, /status, /cancel, /privacy. Acknowledge promptly, then edit meaningful progress rather than streaming every token into chat. Preview links should not expose secrets.
05 / AUTHENTICATION HARNESS

“Connected” is a verified state,
not a saved password.

Connect with consent. Choose an app and account, disclose remote session custody, then open an expiring, authenticated connection view. Prefer official OAuth when viable; otherwise let the user sign in to the actual site in their dedicated browser.

Human handles the sensitive step. Passwords, MFA, passkeys, consent and challenges stay in the secure connection surface—not Telegram messages or model context. Pause agent access to that profile while the human controls it. A phone’s existing cookies/passkeys do not automatically transfer to a cloud VM.

Verify the right account. Check a provider-specific signed-in probe, expected identity and required capability. A successful HTTP status or page title is insufficient. Store account metadata plus opaque session references; expose “Ready” only after verification.

Maintain on demand. Before use, check freshness and grants. On an expired session, try one permitted refresh/renewal path under a lock. If that fails, record “Needs you” and send a connection link. Never loop on passwords, bypass MFA or silently switch accounts.

Resume the exact pending task. Connection completion arrives as an authenticated event, rechecks account/grant versions, then resumes the original intent. Previously approved writes must be re-approved if arguments, identity or contract changed.

Disconnected → Connecting → Verifying → Ready
Ready → Checking → Ready | Refreshing → Ready | NeedsUser
NeedsUser → Connecting                    (human event)
Any state → Paused | Revoked              (owner control)

Events carry account IDs, epochs, expiry and safe error codes.
They never contain passwords, cookies, OTPs or bearer tokens.

Keep one custody authority

Reuse the existing encrypted Unlock backend for owner identity, secrets, grants and session revisions. Treat the VM browser profile as sensitive live working state, not an independently authoritative vault. Assign one profile writer and checkpoint session updates with compare-and-swap revisions.

Preserve the full profile—including localStorage, IndexedDB and required OS key material—where providers need it. The current cookie-oriented SDK is not a complete profile backup format. Prove reboot recovery with the actual browser and provider.

The mobile login bridge is a real work item

Codegraff’s inspected docs expose exec and files, not a ready-made secure browser viewer or public port mapping. Build an outbound authenticated relay from the VM for a narrowly scoped live sign-in view; prove WebSocket/network support in the first spike.

Use one-time user-bound tickets, short expiry, origin checks, no caching/recording, safe keyboard input and explicit takeover. Never publish a raw CDP endpoint or embed arbitrary login pages in an iframe. If Telegram WebView cannot complete a flow, offer an authenticated external-browser handoff.

Do not market this as zero-knowledge. A hosted agent that acts in accounts necessarily has controlled access to session material. Encrypt at rest and in transit, restrict operator access, support step-up checks for high-risk changes, and state clearly what Codegraff, Telegram, the model provider and Curve Labs ThinkFeel can process. Telegram bot chats are not end-to-end encrypted secret chats.

Tool execution contract

Start with sanctioned API/CLI paths when available, browser-driven paths otherwise. Capture request metadata only where useful and consented. HTTP replay is an optimization, not the product identity.

Each contract pins tool/version, schema, allowed origins, account binding, policy version, effect class, precondition, postcondition, timeout, budget, idempotency strategy and safe repair path. Runtime injects secrets from references; no saved headers or embedded passwords.

Pipeline: Observed → Candidate → Validated → Enabled → Quarantined / Retired. Schema drift, identity mismatch or failed postconditions quarantine a tool. Repairs create a new candidate version; the agent cannot upgrade its own permissions.

entity-learn, made native

Use entity-learn for pointer-based live retrieval, schema normalization and BM25 ranking. The inspected code executes shell strings with execSync, writes a home-directory JSON store, caches data for 300 seconds, and silently falls back to stale cache.

Port the pure inference/normalization/ranking behavior into a Tardigrade package. Replace command strings with typed contract references; replace filesystem globals with tenant-scoped projections; replace shell execution with recorded, authorized Effects. Do not run its CLI or bootstrap over all historical logs in production.

Preserve attribution and test parity with pinned fixtures. The README/package declare MIT, but the pinned tree lacks a standalone license file; confirm the notice before redistribution.

First allocationPersist provisioning intent, enforce one per-user lifecycle writer, then POST /v1/sandboxes. Persist returned ID/spec before accepting work. Create idempotency is undocumented: on an ambiguous timeout, reconcile safely or flag operator recovery; never blindly allocate another VM.

IdleAfter work settles, close/flush the browser and checkpoint sensitive state, then stop after a proposed two-minute grace period. Keep Codegraff’s 30-minute auto-stop as a failsafe initially. Supervisor timers live outside the VM. Waiting for a Telegram approval should not keep compute running.
Long task or live loginHold a bounded activity lease. Codegraff counts gateway interaction, not a background process or relay traffic, as activity. Use verified activity-refresh calls while genuinely active, with a hard deadline and cost cap; terminate heartbeats when work ends.
Reboot / credit exhaustionDisk remains; memory/processes do not. Reacquire locks, start runner/browser, validate credentials and reconcile unknown effects. Restore actor state from its outside-VM durable log. A credit failure blocks further spend and notifies the user/operator.

A Codegraff key owns its sandboxes, not a Telegram user. Because the operator key may own every sandbox, Unbrowse must enforce tenant ownership on every lookup and operation. Never give the global Codegraff key to the VM, browser, model or Mini App. Use an authenticated control-plane service to make gateway calls.

CloakBrowser through agent-browser

A trusted supervisor launches launchPersistentContext({ userDataDir, … }) with an explicit loopback CDP endpoint. The runner invokes agent-browser --session … --cdp … --pin-tab --json. The wrapper owns browser launch/close; agent-browser owns agent interaction.

Use a separate process/profile per account when accounts would share cookies. CLI session names and pinned tabs do not isolate cookies in a shared CDP browser. Reacquire targets and accessibility references after navigation/restart; saved @eN references are not durable contracts.

Compatibility gates—not assumptions

Prove Linux libraries, available disk, sandbox/root permissions, persistent-profile reattachment, CDP compatibility, outbound relay, browser sandboxing and stop/start recovery in a disposable spike before rollout.

No production --no-sandbox shortcut. If Codegraff cannot support the necessary security or relay setup, stop the rollout and revisit the VM host. Do not silently weaken isolation or promise that stealth avoids provider challenges.

08 / SECURITY + REPLAY BOUNDARIES

Logs are the control plane.
Secrets are not log data.

Blocking compatibility detail: the pinned agent-browser security guide explicitly rejects --allowed-domains with --cdp, --profile and saved-state restore. Our required persistent/CDP design therefore needs an independent VM egress firewall/proxy and trusted navigation broker. Do not add incompatible flags and call the system isolated.
  • Before browser startup: enforce network egress rules, block metadata/private networks, localhost services except explicit broker/CDP paths, raw sockets and unapproved tunnels. Make the proxy non-bypassable; test DNS rebinding, redirects, WebSockets, service workers and UDP/WebRTC. Allow documented IdP/CDN dependencies per integration.
  • Least privilege: model-authored Code Mode sees only scoped methods. Browser profile and key broker run under a separate restricted identity. Deny raw CDP, shell, cookie dumps, generic eval and secret-bearing files. A domain allowlist alone does not prevent misuse of an allowed site.
  • Data minimization: record argument schemas, opaque references, redacted outcomes, hashes and provider receipt IDs. Strip Authorization, Cookie, Set-Cookie, signed URLs and secret fields before immutable persistence. Hashing a password is not safe redaction. Block screenshots/snapshots during credential entry.
  • Sensitive content: page text and tool results can include private messages and prompt injection. Return only what the current task needs; mark it untrusted. Output filters and content-boundary flags are defense-in-depth, not authorization. Content cannot change policy, grant new tools or request secret export.
  • Retention: proposed default of no credential-screen capture, short-lived encrypted diagnostic artifacts only with opt-in, and 30-day task history with user controls. Separate removable sensitive blobs from the immutable audit skeleton; support tenant-key destruction and an explicit backup-expiry policy.
  • Revocation: cancel queued/running operations, invalidate capability epochs, remove live browser state and enforce the changed grant immediately. Server-side authorization is checked before each effect, not only when a session starts.

Actor log replayRebuild projections from recorded events. Do not re-execute effects whose results are already recorded. Use synthetic/stubbed Effects for historical evaluation.
Fresh readRun an approved read contract with current auth and explicit freshness. Input/schema/identity and pagination checks still apply.

Tardigrade explicitly documents at-least-once external effects. Recorded keyed results are deduplicated, but a crash after a remote action and before its receipt can cause re-execution. This applies to VM allocation, browser mutations and Telegram sends, not just API requests.

Licensing gate: CloakBrowser’s wrapper is MIT; its compiled browser is proprietary under a separate binary license. The pinned license requires a separate OEM/SaaS agreement for customer-facing browser functionality/control. This personal-agent design includes that capability. Obtain written clearance and concurrency pricing before a customer launch; a normal paid subscription does not itself grant SaaS rights.

Bot first. One useful loop.
Then make it compound.

Planning estimate: six to eight engineering weeks for a constrained private alpha with two engineers and design/security support, assuming provider access and licensing are resolved. Not a launch commitment. Security, provider review and licensing can extend the schedule.

Gate 0
Before building

Resolve feasibility and source access

Week 1
Bot foundation

Ship the native Telegram skeleton

Native Aiko channel, verified private-chat identity, durable inbox/outbox, GLM binding, native ThinkFeel expression service, factual reply gate, cancellation and budget enforcement. Add one synthetic read tool and synthetic voice fixtures. No real app credentials yet.

Exit: duplicate updates and actor restarts produce one logical task; spoofed senders are rejected; model/tool errors result in a truthful status; traces survive restart. Measure outbound duplicate behavior rather than claim exactly once.

Weeks 2–3
First real loop

One account, one persistent VM, one verified read

Lifecycle component, scoped runner, Cloak via agent-browser, secure mobile connection, identity probe and on-demand renewal. Wire one approved provider through Unlock. Run the bot → wake → read → receipt → reply → stop loop.

Weeks 3–4
Mobile surface

Replace All logins with Your apps

Weeks 4–6
Repeatability

Native contracts and entity pointers

Integrate verified classic modules, port entity-learn’s pure behavior, learn only successful authorized reads, expose provenance/freshness, add contract quarantine and a second app. Start with curated promotion before automated proposals.

Exit: next use resolves an approved pointer through the native contract without new browser exploration; schema drift quarantines it; stale data is labeled; revocation invalidates cache; unknown/mutating commands cannot be learned.

Weeks 6–8
Private alpha

Add approved writes and operational recovery

Exact-action approvals, write receipts, crash reconciliation, account deletion, cost caps, rate limits, backups/restore drill and support tooling. Invite 10–20 users only after the security gates pass.

Exit: fault-injection suite passes; no unapproved write paths; ambiguous outcomes stop rather than repeat; pilot retention and unit economics are measured weekly.

Acceptance suite that decides whether this works
  • Authentication: valid/expired/revoked session, wrong account, MFA pause, passkey failure, SSO parent expiry, human takeover race and mid-task revocation.
  • Isolation: swapped user/account/sandbox IDs, forged Mini App data, replayed callback, leaked capability, file-path traversal, profile cross-access and egress bypass attempts.
  • Durability: crash before/after VM creation, exec launch, remote action, tool receipt, Telegram send and stop. Inject duplicate and out-of-order deliveries. Unknown writes must not be replayed.
  • Learning: schema inference parity, pointer ID collisions, empty/paginated results, output caps, stale fallback, poisoned page instructions, contract version changes and mutation-pointer rejection.
  • Mobile: 320–1440px, 200% zoom, screen reader/keyboard navigation, modal focus/Back, safe areas, slow/offline network, virtual keyboard, long app/account labels and multiple accounts.
  • Aiko voice: correct persona/name; actual sent history; verified facts survive personification; no false completion claims; mismatched/empty output rejected; ThinkFeel 401/403/404/422/429, cancellation and outage fallback; accepted text reused after restart.
  • Operations: GLM 429/402, search reservation failure, async exec timeout, lost exec ID, VM credit stop, disk full, browser crash, deleted sandbox, restored backups and provider outage.

Retain existing tests; add native Tardigrade method/recovery tests and end-to-end Telegram fixtures. Browser E2E uses isolated browser-harness sessions, never personal Chrome or real vault exports. No production deployment is authorized by this plan.
