Canonical architecture discussion 0.7 →

01 · Build boundary

The management UI handles metadata. A separate trusted runtime retrieves cookie material privately, hydrates once before authenticated navigation, delegates existing browser tools, and syncs a compare-and-swap revision. No execution proxy and no per-run approval prompts.

Revoking access stops future retrieval and synchronization. It does not erase cookies already delivered to a browser or guarantee provider logout.

  • / Overview: derived health counts, attention queue, renewal history.
  • /accounts Searchable vault, source provenance, connection details and revoke.
  • /connect Calm three-step fixture selection → standing assignments → completion. Native password/session, one-time import, live source reference, destination SSO.
  • /agents Create, rename, enable, and assign profiles.
  • /sessions Revision, expiry, renewal, pause and challenge recovery.
  • /sources Imported snapshots versus live references; disconnect and reconnect simulation.
  • /activity Redacted mutation events.

05 · SDK contract

Fetch-based management client, injectable token provider and transport, typed resources, structured safe errors, AbortSignal and request timeout. No automatic mutation retries or secret logging. The separate runtime entry point has cookie adapter import/export, profile/connection binding and revision conflicts. Only fixture cookie values are accepted by the demo API.

06 · Phases and gates

  1. This build: workspace, functional Start API, metadata UX, SDK declarations/tests and isolated browser verification. Production build and deep-link checks are required.
  2. Production foundation: threat model, owner auth, independent OAuth issuer, DB tenancy, encrypted custody with managed keys, audit and revocation policy. External security review before real secrets.
  3. Connectors: one official manager adapter at a time, selected-item authorization, deletion semantics, outage handling. Import parsers must be sandboxed and erase plaintext buffers.
  4. Maintenance: provider-specific supported refresh/login/SSO recipes, serialized jobs, MFA handoff, retry budgets, atomic publication and stale-browser reconciliation.
  5. Runtime distribution: browser-harness wrapper, constrained domains, private IdP contexts, CLI OAuth PKCE/device flow where supported; optional MCP metadata tools.

07 · Explicit gaps

No library here solves arbitrary Google browser SSO, secure isolation inside an unrestricted compromised runtime, or production vault custody. NordPass API suitability is unverified. All source/SSO connections in this demo are synthetic. In-memory workspace is process-scoped and resets on restart; use loopback only. Background transitions are manually simulated, not a scheduler.
