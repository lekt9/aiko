# GraphHarness compiler and registry

**Status:** deterministic preparer, external-attestation admission verifier, and content-addressed registry.  
**Schema:** [`../../schemas/graph-harness-v1.schema.json`](../../schemas/graph-harness-v1.schema.json).  
**Specification:** [HARNESS-SPEC.md](HARNESS-SPEC.md).

GraphHarness turns a bounded graph declaration into a portable, content-addressed package. It makes the graph, membrane, material bytes, acceptance claims, and recursion ceilings inspectable before any runner receives them.

The current command does **not execute nodes, witnesses, or judges**. It does not confine a process, allocate workers, lease work, append Contract rows, commit Neuron firings, or settle the north star. `build` prepares identity and validates; `admit` consumes a Contract-owned attestation without executing; `inspect` verifies either state; `register` stores an already admitted envelope; `find` selects one. This is intentionally **no new scheduler and no new ledger**.

## The lifecycle

The complete lifecycle is recursive because a generated harness can itself become pinned input to a parent harness. It is not one opaque command:

```text
author/generate inert bytes
        │
        ▼
build ──► canonical prepared package + transitive material identity
        │
        ▼
run ───► owning executor, under enforceable confinement       (not implemented here)
        │
        ▼
settle ► independent evidence/judgment + Contract attestation (external)
        │
        ▼
admit ──► verify complete bindings; state becomes admitted (no execution)
        │
        ▼
register ► immutable CAS object + name/version reference
        │
        └── find/inspect/reuse; changed inputs start a new lifecycle
```

For a recursively generated child:

1. The generator and all source bytes exist before the child is pinned.
2. The child receives no more than the parent's remaining depth, child, total-node, wall-time, and tool-call budgets.
3. The child is built and inspected as its own package. A parent may cite it from `provenance.source_digests` with the GraphHarness media type; inspection recursively verifies the child's closure and records its `transitive_digest`.
4. An actual integration must run, judge, and durably settle the child before treating its result as satisfied.
5. Only then should policy register it for reuse and let the parent consume its pinned result.
6. Any generated descendant records `parent_package_digest`; it may not name its own subject digest as its parent.

The checked-in compiler implements the packaging recursion in step 3. It emits `admission.state: "prepared"`, never behavioral `admitted`. Execution and judgment remain external. A separate `admit PREPARED --attestation FILE -o OUT` verifies a structured, authenticated Contract-owned attestation and is the only compiler route to `state: "admitted"`. The attestation is bound to the prepared subject and transitive digests, every node and north-star witness ID, the exact declared independent judge implementations and verdict references, a pinned `admitted_by`, `admitted_at`, `evidence_refs`, and a mandatory `ledger_ref`. `admit` resolves the attester bytes but executes no witness or judge. The admitted envelope preserves verdict bindings, authentication, and the complete attestation digest.

This separation is load-bearing: generated bytes precede their pin, compilation alone does not prove behavior, and the producer never settles on its own word.

## Commands

Run the repository-native wrapper from the repository root:

```sh
bin/aiko-harness --help
bin/aiko-harness self-test
```

### Build a deterministic package

A problem declaration has the complete GraphHarness envelope shape, but compiler-derived digest and closure fields may be absent or stale. References resolve relative to the input directory unless `--root` is supplied.

```sh
mkdir -p /tmp/aiko-harness-demo
bin/aiko-harness build \
  tests/fixtures/graph-harness/chain.problem.json \
  --root tests/fixtures/graph-harness \
  --output /tmp/aiko-harness-demo/chain.harness.json
```

`build` validates schema and semantics, verifies referenced local bytes, derives `subject_digest`, `dependency_closure`, and `transitive_digest`, sets `state: "prepared"`, and atomically writes canonical JSON. It discards caller-supplied admission claims. The same declaration and reference bytes produce the same output.

References currently accept package-relative paths and local `file:` URIs only. They must resolve to regular files inside the trusted reference root. Network schemes, remote file authorities, query/fragment suffixes, missing files, root escapes (including resolved symlinks), and digest mismatches refuse.

### Admit from Contract-owned evidence

```sh
# Deployment/service-manager bootstrap; never derive this from a request.
export AIKO_CONTRACT_VERIFY_KEY=/run/aiko/contract-ed25519-public.pem
bin/aiko-harness admit /tmp/aiko-harness-demo/chain.harness.json \
  --attestation /tmp/aiko-harness-demo/contract-attestation.json \
  --root tests/fixtures/graph-harness \
  -o /tmp/aiko-harness-demo/chain.admitted.json
```

The attestation has `api_version: graph-harness-attestation/v1`, `kind: GraphHarnessAdmissionAttestation`, and `owner: contract`. It must reproduce the prepared subject/transitive digests; provide exactly one `{witness_id, judge, verdict_ref}` for every node and north-star witness; match each package-declared judge identity; include every verdict reference in `evidence_refs`; and provide pinned `admitted_by`, RFC 3339 `admitted_at` with the required uppercase `T` separator, mandatory `ledger_ref`, and authenticated Contract authority. Missing, duplicate, forged, mismatched, or extra verdict bindings refuse. This validates a Contract assertion; it does not query Contract or execute any witness.

There is no public key-selector option. `AIKO_CONTRACT_VERIFY_KEY` is mandatory process-bootstrap configuration and must be an absolute path to a deployment-pinned PEM Ed25519 **public** key. The MCP service must sanitize and pin this environment before accepting requests; request, command, package, and attestation data must never influence it. The file must be a regular non-symlink file of 1 through 65,536 bytes. Contract retains exclusive custody of the corresponding **private signing key**; the compiler needs no signing secret. The attestation's required `authentication` is `{"algorithm":"ed25519","key_id":"sha256:<SHA-256 of DER SubjectPublicKeyInfo>","value":"<128 lowercase hex>"}`. Compute `value` by signing canonical JSON of the **complete** attestation with only `authentication.value` replaced by `""`. The compiler derives DER and key identity and verifies with fixed `/usr/bin/openssl`; it uses 0600 temporary message/signature files, fails on any nonzero exit, and never interprets stdout as proof. This signature is the authority that vouches for Contract ledger, verdict, and evidence references; the literal `owner` field is not authority.

Because the signature covers the entire statement, it also covers both prepared digests, `admitted_at`, all references, and judge identities. A captured attestation cannot be altered or replayed onto different package/closure bytes. Exact-statement replay remains possible and harmless at this packaging layer; Contract owns issuance freshness, revocation, and public-key rotation policy because this compiler deliberately has no clock or ledger.

### Inspect at a trust boundary

```sh
bin/aiko-harness inspect \
  /tmp/aiko-harness-demo/chain.harness.json \
  --root tests/fixtures/graph-harness \
  --json
```

The compact result reports the explicit `state`, distinct `prepared`/`admitted` booleans, name, version, node/material counts, subject digest, and transitive digest. Without `--json`, `inspect` emits the verified canonical envelope. Inspection re-resolves material and verifies the canonical closure; it does not run acceptance.

Use `inspect`, not registry presence alone, when material bytes are available and the full transitive closure must be re-established. The registry checks schema, metadata identity, and `/package` digest but deliberately does not fetch and replay the compiler's closure, witnesses, or judges.

### Register and find

```sh
# The register process receives the same sanitized deployment bootstrap.
export AIKO_CONTRACT_VERIFY_KEY=/run/aiko/contract-ed25519-public.pem
bin/aiko-harness register \
  /tmp/aiko-harness-demo/chain.admitted.json \
  --registry /tmp/aiko-harness-demo/registry

bin/aiko-harness find fixture-chain \
  --registry /tmp/aiko-harness-demo/registry \
  --version 1.0.0 > /tmp/aiko-harness-demo/found.json

# Or select the highest compatible semantic version:
bin/aiko-harness find fixture-chain \
  --registry /tmp/aiko-harness-demo/registry \
  --min-version 1.0.0 \
  --tag fixture
```

`register` uses the same deployment-bootstrap public verifier key and refuses unauthenticated or internally inconsistent admitted input. Before fresh publication it recomputes the package subject, canonical closure/transitive identity, exact verdict/evidence bindings, complete attestation digest, key identity, and Ed25519 signature. It writes canonical envelope bytes once under `objects/sha256/<prefix>/<envelope-digest>.json`, then writes an immutable `refs/<name>/<version>.json`. It fsyncs, independently reads the bytes back, deduplicates an identical repeat, and refuses a name/version conflict or mutated object. CAS publication is durable storage, not Contract settlement.

`find` supports exact `--version`, minimum `--min-version`, repeated `--tag`, and `--projection aiko_skill_v1|cell_v0`. Without an exact version it chooses the highest compatible SemVer, with digest as a stable tie-break. It emits the complete envelope, not just a path.

## What `build` proves

The compiler fails closed over the following preparation properties; behavioral admission additionally requires the external attestation described above.

### Shape and canonical identity

- The envelope matches `graph-harness/v1`; unknown fields refuse.
- JSON is canonicalized using RFC 8785 ordering for the schema's integer-only domain. Floating-point values, non-I-JSON integers, and invalid Unicode refuse.
- `subject_digest` is SHA-256 over canonical `/package` only. `admission` and `registry` remain outside that subject, avoiding self-reference.
- Registry name, version, and description exactly match package metadata.
- Every schema, Cell declaration, skill declaration, pinned source, witness, judge, generator, admitter, and compatibility Cell projection is resolved and byte-hashed.
- `dependency_closure` is canonical and deduplicated by complete closure entry. `transitive_digest` hashes the subject-digest object together with that closure. A nested GraphHarness source contributes its verified transitive digest.

A source edit, witness edit, skill-document edit, or nested-package change therefore changes or invalidates the material closure even when `/package` text itself was not edited.

### Data graph

- Node IDs are unique; dependencies exist; self-dependencies and cycles refuse.
- Edges are in canonical lexical order and may not cross the membrane backwards.
- `$input`/`$output` ports exist; node edge ports match declared `reads`/`produces`.
- Every `depends_on` currently requires a matching explicit node-to-node **data edge**.
- Every incoming node port is a declared read. An unbound read must exactly name a pinned grounding source.
- Every declared product must be carried by an outgoing edge to a descendant or membrane output.

This compiler uses Kahn traversal only to reject cycles and calculate static depth/fan-out. It emits no frontier and launches nothing. The broader specification permits data, evidence, authority, or settlement edges, but the v1 compiler currently accepts dependencies only when represented by explicit data edges. There is no implemented settlement-only edge encoding.

### Grounding and independent acceptance shape

Every node must contain at least one pinned skill declaration, pinned source, or honest capability gap. For each skill, the compiler first verifies the byte digest, then parses those exact bytes as `SKILL.md`: UTF-8, closed YAML frontmatter, exactly the required non-empty `name`, `description`, `probe_input`, and `expect_contains`, with `name` equal to the grounding name. Duplicate, unknown, missing, unsupported, or free-text declarations refuse. Generated walk diagnostics retain name, ref, and digest. The compiler does not activate the skill or prove its method works.

Each node and the package north star declare a structured witness and an independent judge. The compiler verifies referenced bytes, evidence names/references, expected-artifact coverage, quorum bounds, and that judge and producer do not share a reference or digest. North-star judge identity is compared with every node implementation.

That independence check is syntactic implementation separation, not proof of organizational or authority independence. Witness argv, timeouts, expected exit codes, evidence collection, verdict schema validation, and judge execution are declarations only today.

## Membrane, resources, and effects

The membrane is the maximum declared authority:

```text
inputs/outputs: typed ports pinned to schema bytes
authority:      filesystem, network, process, secret scopes
```

Node `writes`, supported resources, and supported effects must be lexically inside those scopes. A filesystem resource in write mode must also appear in the node's `writes`. Current semantic enforcement maps filesystem, network, process, and secret resources. Although the schema reserves `device`, `service`, and `other`, the compiler refuses them because it has no enforceable membrane mapping. Likewise, effect kinds with no mapping (including `other`) refuse.

These are conservative declarations, **not OS confinement**. A clear authority check does not show that Python, exec, a Cell leaf, or an external program lacked ambient access. `exclusive: true` does not acquire a lock. The compiler does not detect pairwise write/resource collisions; `collision.problem.json` is a valid declaration useful to a future runner/policy, not a promise of safe concurrency.

Effects make invalidation policy explicit:

- `none` must be local, non-boundary, `not-applicable`, and `recompute`.
- Filesystem, message, payment, deployment, and remote-mutation scopes must fit membrane authority.
- An external-boundary effect must declare `readback: required` and `on_invalidation: compensate-never-replay`.
- Its node witness must expose `boundary-readback` evidence consumed by the independent judge.

The compiler verifies those declarations. It does not send, read back, or compensate.

## Invalidation, redrive, and compensation

A reusable package supplies the identity and policy needed by the reactive path, but the owning runtime creates the facts:

1. Contract records durable occurrences and invalidates superseded obligations and dependants.
2. An executed Neuron firing cites every actual source in `evidence[].sources` and attaches products with `produced_by`. Package provenance does not substitute for those firing citations.
3. `telemetry stale` reconstructs derivation movement from committed citations.
4. `aiko redrive` consults live topology and chooses exactly one route:
   - deterministic, runnable, nothing crossed: re-fire under a new firing ID;
   - not mechanically runnable, nothing crossed: open an agent goal;
   - independently read-back boundary crossing: create a `CompensationGap` over old and new products, never replay the stale effect.

A registry record and a GraphHarness effect declaration cannot establish that a boundary was crossed. Only execution/read-back evidence can. A runner must also keep non-deterministic model work at terminal edges or behind pinned input identity; deterministic recomputation is the convergence proof.

## Bounds and convergence

`package.recursion` declares ceilings for depth, children per node, total nodes, aggregate wall time, and tool calls, with mandatory `on_exhaustion: refuse`.

Today `build` checks the static graph against:

- node count ≤ `max_total_nodes`;
- longest dependency depth ≤ `max_depth`;
- maximum direct fan-out ≤ `max_children_per_node`;
- node-witness count plus north-star witness ≤ `max_tool_calls`;
- sum of declared witness timeouts ≤ `max_wall_time_ms`.

These are compatibility checks, not clocks or counters. No current GraphHarness command decrements a parent's remaining budget, stops a process at the wall-time ceiling, counts runtime tools, expands nodes, or judges convergence. A confined recursive runner must monotonically reduce remaining budgets, pass children the smaller of child ceilings and parent remainder, refuse exhaustion, and never silently truncate descendants while claiming the north star passed.

Local convergence comes from deterministic producers plus falsifiable node witnesses. Package convergence comes from the independent north-star verdict. Reactive convergence requires citations and the three-case redrive rule. None is established merely by successful compilation.

## Ownership: compose the existing graphs

| Layer | Owns in the lifecycle | Must not be inferred from GraphHarness |
|---|---|---|
| **Aiko host/registry** | Schema/digest membrane, compiler/registry CLI, discovery, explicit adapters, composition. | A new scheduler, durable settlement, or automatic execution. |
| **Contract** | Pure walk analysis when asked; durable declarations, leases, evidence, occurrences, invalidation, and settlement in its existing substrate. | Cell-local execution or truth derived from a registry file. |
| **Cell** | Typed ports, deterministic local Kahn traversal, executor checks, and canonical manifests for referenced `cell/v0` implementations. | Contract durability or safe parallelism from topology alone. |
| **Neuron** | Standalone firing identity, committed citations/products, stale facts, and three-case redrive. | Contract planning, package admission, or observer guesses about unseen topology/effectors. |

GraphHarness is a transport/admission membrane across these owners, not a fourth graph runtime. A Contract walk, Cell declaration, Neuron firing, and GraphHarness envelope are related but not interchangeable. Neuron must remain independently buildable without Contract.

## Compatibility and reuse

The media type is `application/vnd.aiko.graph-harness+json;version=1`; breaking package semantics require a new `api_version`. Changes to behavior create a new package version and subject/transitive identity. Registry tags are filters, not authority.

Compatibility projections are deliberately weaker views:

- `aiko_skill_v1` exposes name, description, probe input, and `expect_contains` for legacy discovery. Its string probe cannot replace structured node/north-star acceptance.
- `cell_v0` points to separately pinned Cell bytes. It does not convert the package into a Cell or prove the Cell executed.

There is no automatic, lossless conversion to a Contract walk, Cell YAML, or Neuron firing. Every adapter must be explicit and pinned and must preserve membrane, evidence, bounds, and effect policy or refuse. `find` matching a SemVer, tag, or projection means “compatible with this query,” not “safe to execute in the caller's environment.” Inspect bytes and compare authority before reuse.

## Current limits

The checked-in implementation intentionally stops before execution:

- no `run`, `judge`, `settle`, `redrive`, or recursive-expansion command;
- no process/container sandbox and no enforcement of declared authority;
- no scheduler, frontier output, lease, lock, resource arbitration, collision rejection, retry, or reconciliation;
- no witness/judge invocation; `admit` authenticates and verifies attestation bindings but relies on the Contract Ed25519 signing authority to vouch for referenced row contents;
- no Contract append or ledger query; admitted state requires a non-empty Contract `ledger_ref` covered by the authenticated attestation;
- no Neuron firing/citation/product commit;
- no runtime budget counters or descendant budget propagation;
- no remote reference fetch; local files only;
- no automatic compatibility conversion;
- registry behavior is separate; only an envelope whose explicit state is `admitted` is eligible for publication policy.

The fixtures are declarations, not executed demonstrations. `chain`, `fanout`, `collision`, and `effect-boundary` exercise packaging shapes. `invalid-edge`, `invalid-digest`, `invalid-bounds`, `invalid-grounding`, and `invalid-effect` exercise refusal. Their small Python witness/judge files are hashed material; the compiler does not call them.

## Staged route to confined execution

Execution can be added without changing ownership or duplicating machinery:

1. **Policy preflight.** `inspect` the package and closure; compare requested membrane authority with a caller policy; reject capability gaps, collisions, unsupported executors, or weaker compatibility projections.
2. **Pinned adapter.** Translate each admitted `cell/v0` node through an explicit pinned adapter. Ask Contract for durable readiness/leases when the work is durable; use Cell's runtime only for the typed local graph it owns. Do not copy Kahn scheduling into this compiler.
3. **Mechanical confinement.** Start nodes only in an executor that can enforce declared filesystem, network, process, and secret authority. Treat unenforceable declarations as refusal, not “best effort.” Preserve lexical/deterministic joins where required.
4. **Evidence edge.** Execute pinned witness argv with enforced timeout, collect named artifacts/durable state/boundary read-back, then run the separately pinned judge and validate the verdict schema. A process exit alone cannot settle an artifact or effect claim.
5. **Durable truth.** Have Contract record leases, evidence, refusal/exhaustion, and settlement. Commit actual Neuron citations and products for reactive visibility. The compiler and registry remain stateless about execution.
6. **Effect discipline.** Require independent read-back before marking a boundary crossed; on later invalidation route crossed work to compensation and prohibit replay.
7. **Bounded recursion.** Carry monotone remaining budgets into descendants, run the entire child lifecycle, and bind the child transitive digest and verdict into parent evidence.
8. **Publication.** Register only after the deployment's settlement policy passes. Reuse starts with `find`, then fresh `inspect` and authority comparison; it never starts by trusting a name alone.

Each stage has a refusal boundary and can be gated independently. The route reuses Contract for scheduling/durable truth, Cell for local execution, Neuron for committed reactive provenance, and Aiko for composition. It adds adapters and confinement—not another scheduler or ledger.

## Acceptance for the current surface

```sh
python3 scripts/graph_harness.py --self-test
python3 scripts/graph_harness_registry.py --self-test
bin/aiko-harness self-test
```

The graph node that introduced the full fixture/refusal gate uses:

```sh
bash tests/graph-harness-builder-gate.sh
```

That gate is the behavioral authority once present. Passing compiler/registry tests proves deterministic packaging, refusal, immutable storage, and lookup behavior covered there. It does not prove execution or settlement, because those are outside the current surface.
