# Aiko → Cell → Aiko synthetic benchmark

This receipt evaluates the bounded local path requested by the Hoysan example without reading customer spreadsheets, PDFs, images, names, or rosters. Inputs are generated by `tests/fixtures/hoysan-synthetic/generate.py` and use only `SYN-*` identities.

## What was executed

```text
bounded authoring → authored roster tool
actual Hoysan draft Cell → hard operational validation
self-wire Cell → generated Aiko seat harness → materialize/build/fire child
Aiko doctor → bind authored Cell into a graph plan
Smithers runCell adapter → fire actual Hoysan Cell and propagate refusal
```

Runnable receipts:

```sh
bash tests/hoysan-fractal-e2e-gate.sh
python3 tests/hoysan-fractal-benchmark.py --iterations 10 \
  --out zig-out/benchmarks/hoysan-fractal.json
```

The benchmark records observations, not a flaky wall-clock acceptance threshold. Determinism and refusal are binding gates; latency is diagnostic.

## Defects found and fixed

1. The old “Hoysan E2E” ran a generic two-worker roster transform, not `hoysan_draft.py`.
2. An infeasible draft returned `validation.ok=false` with a successful firing, allowing a partial product and manifest to be retained.
3. Missing rest duration on an NTS shift change degraded open instead of refusing.
4. Duplicate worker ids and unknown pools lacked named input refusals.
5. `aiko-doctor` was optional in the old gate.
6. The Smithers step printed success and ran only generic adapter tests.
7. `runCell` left its temporary input directory behind.
8. Account handles embedded tenant/origin/account identity and trusted caller-selected `cred:` ids.

The new gates cover exact gang composition, global worker uniqueness, WAH and exception rules, NTS standby uniqueness, provenance digests, hash-seed/input-permutation determinism, named negative cases, no retained result/manifest on refusal, generated-seat materialization, and the actual Hoysan Cell through `runCell`.

## Honest remaining blocker

The Smithers control plane is now the default distribution (Cell + `control` package). The `aiko-packages` installer auto-installs `smithers` as an Aiko plugin when `aiko-flow/` and its `node_modules` are present, and `DiscoveryConfig::populate_plugin_lists` default-enables the installed `smithers` plugin so no manual `aiko plugin enable` or integration flag is needed. A bare source tree without `aiko-flow/node_modules` falls back to a Cell-only install with a warning — this accommodates the public `github.com/lekt9/aiko` clone path where `aiko-flow/node_modules` may be absent (the `aiko-flow/` source is tracked in the monorepo; its dependencies are not installed by default), and should not be confused with an intentional opt-in surface.

The remaining unproved boundary is durable Smithers scheduling/resume witness coverage on real gateway-run surfaces, not whether the harness is installed. Inventing upstream scheduler internals here would be a fabricated green.

## Repository acceptance-gate audit

The benchmark-specific gates are green. A full `zig build gate` was also attempted. Two root gate bugs were repaired (`timeout` disappeared from the deliberate no-PATH probe; `wc -l` padding made equal bridge counts compare unequal). The remaining published-interface witness is not green on this macOS host because curl cannot bind the synthetic second peer address `127.0.0.2` (`CURLE_INTERFACE_FAILED`, exit 45). That witness needs a host with the alias configured or the Linux acceptance environment; weakening its two-peer isolation assertion would invalidate the gate.
