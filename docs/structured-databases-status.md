## Registered-read checkpoint — 2026-09-08

- Added a host-owned adapter from database request bindings to the existing learned Merkle read contracts and `executeHarnessAction`. Node and Worker resolve contracts from the owner's journal, recheck connector/session authority and generation, and reuse existing transport. Bindings cannot turn arbitrary URLs into source requests. The source catalog exposes contract/input/step metadata through the native tool, API and SDK; listing does not grant execution authority.
- `table_refresh` admits a bounded native operation with a sealed plan, grouped invocations and independently recoverable group commits. Identical inputs share one request across selected fields/rows. Calls, response bytes, rows and duration are bounded; an uncooperative source promise times out. Lost group settlement recovers its atomic store receipt without another fetch. An interrupted attempt reserves its unknown costs and prevents later dispatches in that occurrence. Receipts distinguish measured costs from reserved budgets.
- Plans capture input table/row revisions, source value versions, source generations and transitive access/retention evidence. Commit rechecks local dependencies in the SQLite transaction. A foreign lookup input changing during a request discards its result; later input changes withhold already-cached results. Unchanged checks preserve input value versions. Expired input freshness prevents a new commit. A failed refresh cannot expose a value fetched for an older input or connection generation.
- Materialized derived fields retain input dependency evidence, so query/snapshot authorization follows their original inputs. A reference-only input cannot silently become a retained output. Raw response bodies and selected reference-only values remain absent from durable database/native records. Reference-only values still have no transient query delivery path; this checkpoint implements manual checks and eligible selected-value materialization only.
- Queries now evaluate selected fields plus actual filter/sort/formula/lookup/join dependencies. A local projection does not authorize or evaluate unrelated live columns. Exact row-ID filters use an indexed row read. Empty selected source projections retain direct column retention evidence; schema-wide transitive treatment remains open.
