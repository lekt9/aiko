# Unlock universal connector

Product direction, clarified 9 September 2026: remove the continuous setup and integration-building that prevents agents from doing useful work. Connect an identity once, discover its existing apps, establish and retain their authorised sessions, then browse and index internal API dependencies as reusable graphs. Google is the first discovery/sign-in starting point; authenticated applications and socials are core scope. Other existing app sessions can join through their supported private connection path.

The same browser memory should let agents recall relevant operations, fetch current context, understand the user across apps, and reuse verified actions with fresh inputs. An initial scoped indexing sweep and incremental maintenance prepare the environment before each new task; users should resolve genuine exceptions rather than reconnect and explain every app repeatedly. See [product prioritisation and the cross-app acceptance story](product-prioritisation.md).

This is the target product contract, not a claim of universal provider support or deployment. Google-linked discovery, app-session verification, indexing permission and action authority are distinct. Retain current owner isolation, private credential custody, native execution, approvals and uncertain-effect receipts. Existing provider catalogs and API integrations remain usable routes alongside browser-learned capabilities; they do not define the product's coverage ceiling. Never collect credentials in chat.
