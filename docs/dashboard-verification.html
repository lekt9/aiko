The boundary is intentional.

All account records and session cookies are synthetic. No real secrets, external account logins, production vault encryption, live password-manager integrations or OAuth issuer are connected. The process-local API is unauthenticated and must not be publicly exposed.

What ships

The workbench

  • Overview counts derived from the fixture dataset.
  • Search, filters, sorting and deep-linked account details.
  • Five connection-method demos; import preview with duplicate skipping and standing profile assignment.
  • Profile creation, rename, enable/disable, assignment and unassignment.
  • Session revision updates, maintenance pause, challenge recovery, source outages and truthful revocation.
  • Redacted activity, validated OAuth configuration, developer examples, settings/reset and keyboard command palette.

The SDK and local API

  • ESM package with declarations and zero runtime dependencies.
  • Fetch transport, dynamic token hook, timeout, AbortSignal and safe structured errors.
  • Metadata-only management import; separate private-runtime import.
  • Dedicated browser adapter contract, one-time hydration, serialized lifecycle and compare-and-swap sync.
  • Real HTTP smoke tests on both dev and production: seven checks each, including ten deep links and a 404.
  • Strict synthetic schemas, process-local limits, no secret logging or automatic write retries.

Issues found and fixed

  1. Challenge bypass through pause/resume: pausing now preserves an outstanding challenge; recovery is explicit. Paused, unexpired sessions remain usable without renewed maintenance.
  2. Existing profile descriptions could not save: a restrictive label validator rejected seed punctuation. Description validation is now distinct, with unit and real UI regression coverage.
  3. Mobile text squeezing: attention and runtime strips now stack the action below a properly sized text track. Geometry assertions guard against a recurrence.
  4. Accessibility: darkened secondary text and revision denominators, named the icon-only mobile command button, and made horizontal activity/client/code regions focusable.
  5. Dependency audit: removed an unused Playwright dependency carrying a high-severity browser-download advisory. E2E runs through browser-harness; final audit reports zero known advisories.

Review and known limits

Code / security review

Correctness, architecture, security, readability and performance were reviewed natively. Strict TypeScript and unused-symbol checks pass. Metadata and runtime imports are separate; no production security is claimed. API state is bounded but not durable, tenant-isolated or authenticated. Successful SDK responses are typed, not runtime-schema-validated. Trusted host code must coordinate browser activity around cookie capture.

Hallmark review

Modern-minimal Cobalt workbench, local Space Grotesk + Inter + JetBrains Mono, named color tokens, persistent sidebar with command search, quiet metadata footer, no decorative browser chrome or invented proof metrics. Critique: Philosophy 4, Hierarchy 4, Execution 4, Specificity 5, Restraint 5, Variety 4. This is not a blanket 58/58 certification: compact data controls and optical spacing are deliberate workbench adaptations.

  • Renewals and provider challenges are manually simulated, not scheduled jobs.
  • One-time import selects one fixture per flow; real CSV/JSON parsers and bulk import are deferred.
  • No production browser-harness adapter, CLI, MCP server, OAuth issuer or Google sign-in. Their examples are explicitly contract sketches.
  • Disabling/revoking stops future retrieval and sync, not cookies already delivered or guaranteed upstream logout.
  • Chromium was verified. Safari, Firefox, real touch devices, assistive technologies and production security require separate review.
  • Production decisions and source/license constraints are in the build plan. Bitwarden’s root SDK agreement is restrictive; Buttercup is archived; neither is silently adopted as a vault core.
