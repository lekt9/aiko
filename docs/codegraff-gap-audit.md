**Aiko / Unlock versus CodeGraff — source audit, 8 September 2026**

This document records the baseline before implementation. See [native harness parity](native-harness-parity.md) for the subsequent changes, direct verification and remaining deployment boundaries.

Aiko already has parallel programmatic tool calls. Its largest gaps against CodeGraff are the breadth of agent orchestration, native multi-call handling, incremental execution, persistent working data, provider-aware context management, and the packaged coding workflow.

Scope: the current Unlock working tree, especially `apps/agent`, compared with a fresh public CodeGraff checkout at [`eaa57f2df28b789b8888ebfdd854db975718a765`](https://github.com/justrach/codegraff/tree/eaa57f2df28b789b8888ebfdd854db975718a765). Unlock HEAD was `fdcb5a173cff17d1efbc7b2b97ee91408c2e4fd1`, with extensive existing modified and untracked implementation files; findings include those files. This is a source and local-fixture comparison, not a claim about the currently deployed Aiko Worker or a measured performance comparison. CodeGraff's CLI/desktop agent is the comparator; its inference gateway and sandbox API are infrastructure Aiko already consumes.

Evidence labels: **confirmed** means an explicit implementation boundary or local probe; **partial** means related functionality exists but has a narrower contract; **not found** means no equivalent appeared in the inspected runtime, host assembly, SDK, or tool catalog. The latter is not proof that an arbitrary script could never implement it. Priorities below reflect likely usefulness to Aiko, not feature-count parity.

**Parallelism: what is actually present and missing**

| Layer | Aiko today | CodeGraff today | Finding |
|---|---|---|---|
| Multiple tool calls in one model response | Installed Tardie `actionOf` selects `execute`, otherwise the first call. It returns a single action. | `runTools` accepts the call array and fans external calls out through the I/O pool. | **Confirmed gap.** Additional native calls do not survive Aiko's decode as executable actions. |
| Multiple calls inside one program | `execute` supports `Promise.all`; host package calls really overlap. | RLM and native batches support parallel work. | **Present.** Do not add a second batching tool just to get basic concurrency. |
| Fast branch continues while slow branch runs | Host collects the whole segment batch with `Promise.all`, then replays the program with all results. | The workflow pipeline runs each item through its own stages without a global phase barrier. | **Confirmed limitation.** Aiko's fast branch waits for unrelated slow siblings at the segment boundary. CodeGraff's ordinary native batch also joins the whole batch; its pipeline is the relevant advantage. |
| Separate code executions on one thread | Code reactor considers the oldest unfinished execution and breaks even if it is parked and not ready. | Background agents and jobs allow work to continue outside the foreground call. | **Confirmed limitation.** This does not serialize all account threads or all calls within one execution. |
| Tool work during model generation | Code execution begins after inference produces an action and the complete script is dispatched. | RLM's streaming argument path starts recognized closed literal calls while source is still arriving. | **Confirmed gap:** speculative programmatic tool calling. |
| Dependency-aware tool workflows | Existing JSON workflow runner batches reads, runs writes exclusively, and binds outputs to dependent steps. Default concurrency 4; maximum 8. | Tool batches plus agent phases/pipelines. | **Present but narrower.** Aiko's tool DAG is not CodeGraff's multi-agent pipeline. |

Aiko evidence: [sandbox batch adapter](../apps/agent/src/code-sandbox.ts:21), [runner](../apps/agent/src/code-sandbox-runner.ts:8), [workflow scheduler](../apps/agent/src/tool-workflows.ts:224), [installed model decoder](../apps/agent/node_modules/tardie/src/model/model.ts:129), [installed code reactor](../apps/agent/node_modules/tardie/src/code/execution/reactor.ts:473). Dependency links require this workspace's installed dependencies. CodeGraff evidence: [native batch dispatcher](https://github.com/justrach/codegraff/blob/eaa57f2df28b789b8888ebfdd854db975718a765/src/agent_tools.zig#L72), [pipeline](https://github.com/justrach/codegraff/blob/eaa57f2df28b789b8888ebfdd854db975718a765/src/workflow_pipeline.zig#L1), [streaming RLM](https://github.com/justrach/codegraff/blob/eaa57f2df28b789b8888ebfdd854db975718a765/src/rlm_spec.zig#L1).

The `parallel_tool_calls: false` setting in [model-routing.ts](../apps/agent/src/model-routing.ts:113) is specifically the Cerebras adaptation. It is not a global prohibition on `Promise.all`. Merely changing that flag would not solve the single-action decoder. In code mode Aiko intentionally exposes `execute` as its composer, so the immediate issue is honest handling of unexpectedly wide native responses and the non-code path, rather than assuming every task currently loses calls.

Local probes used the installed decoder and actual QuickJS segment runner, with synthetic host functions and no model/network calls:

```text
Two native calls, first_read + second_read:
  decoded action = first_read only
Native calls, first_read + execute:
  decoded action = execute only

Promise.all([slowRead(), fastRead().then(followFast)]):
  maximum simultaneous host reads = 2
  trace = start slow, start fast, end fast, end slow, follow fast
  segment executions = 3

Set globalThis.auditVariable in one execute; read typeof in the next:
  result = "undefined"
```

The branch trace establishes an execution barrier; it is not a production latency benchmark. Three segments mean the program is evaluated for the initial reads, their dependent continuation, and the final result. The runner creates a fresh VM each time and reproduces previous calls from recorded history. Long chains therefore incur repeated source evaluation and history transport; their actual cost needs measurement.

**Capabilities that should not be put on a missing-feature backlog**

- Parallel reads and dependency-bound tool workflows already work, including exclusive writes in the JSON workflow runner.
- Scoped research children already exist on the hosted path. Background indexing/reflection and experiment child actors also exist, with different permissions and lifetimes.
- Shell commands, filesystem work, Node/Python execution, package installation, outbound HTTP, detached compute jobs, polling and cancellation exist through `sandbox_exec`/`sandbox_job` when mounted. The pure JS composer deliberately has no direct OS globals.
- Tool discovery and schema validation exist through `tools.search`, `tools.describe`, `tools.call`, and the connector router. General MCP compatibility is the gap, not all dynamic discovery.
- Client context compaction, durable logs, recovery, owner isolation, cancellation and uncertainty receipts are implemented.
- Model fallback, routing by conversation/RAG/browser role, request allowances and stream accounting already exist. The model choice is not universally hardcoded to one provider/model.
- Private memory, reusable workflows, immutable harness artifacts, fixed verifiers, acquisition and optimization experiments exist. Full self-improvement parity is not established merely by the presence of these modules, and it would also be wrong to label them absent.
- Telegram typing, activity drafts, message updates, progress mechanisms and underlying inference streaming exist. A missing desktop activity UI is not evidence that Aiko cannot stream or report progress.
- Media interpretation, voice, browser learning, secure account connections and cloud backups exist in source, subject to host/configuration and their own verification. This audit did not live-test them.

The [CodeHarness](../apps/agent/src/code-harness.ts:167) tells the model to parallelize independent reads. The generic `tools.call` facade itself does not classify and serialize every mutation; the separate JSON workflow scheduler does. Before widening concurrency, unify effect classification and resource locks for shared browser/account/file state. CodeGraff's native dispatcher also fans out gated external calls; this audit did not establish that it supplies a universal conflict-aware scheduler. Treat that as Aiko engineering work, not an unsupported claim of CodeGraff superiority.

**Recommended implementation order**

1. **Close correctness and host gaps first.** Make multi-call decoding preserve every call or explicitly reject unsupported batches; do not silently discard them. Add Bun child-thread ownership/actor/layer assembly and test both production hosts. Give research children an explicitly scoped page-read capability.
2. **Generalize the existing worker contract.** Add capability-scoped worker types, model/effort pins, background handles and owner-linked cancellation. Introduce isolated workspaces before allowing parallel edits. Reuse native actor routing and receipts.
3. **Improve how working data is reused.** Add owner-scoped result handles with slice/filter/project operations and explicit retention. Add retained program bindings only with clear replay, lifetime and authority rules. Preserve private result custody.
4. **Remove avoidable barriers where measured.** Let independent workflow items progress on completion, without changing invocation identities or replaying mutations. Then consider speculative execution of verified read-only calls while source streams; arbitrary writes should not speculate.
5. **Unify model context policy and measure caching.** Derive compaction from the selected route; record input/output/cache tokens and first useful output. Add native provider features only on supported routes.
6. **Expand the ecosystem around demonstrated demand.** General MCP, repository tooling, compatible skill discovery, completion verification and ACP should follow the intended use cases. Desktop parity is a separate product decision.

For measurement, use fixed same-model tasks covering parallel search, fast/slow branched reads, large-result filtering, long-context recall, worker implementation plus review, and mid-flight cancellation/restart. Keep fixture data, tools, model route, warm/cold state and completion checks identical. Record correctness, wall time, model/tool counts, token/cache usage, and unknown external outcomes. Test hosted and local paths separately. CodeGraff's published benchmark numbers cannot substitute for this comparison.

**Validation and limits**

Ran `bun test test/code-sandbox.test.ts test/code-harness.test.ts test/model-routing.test.ts test/tool-workflows.test.ts` from `apps/agent`: **53 passed, 0 failed; 344 assertions**. Coverage includes parallel tool workflows, exclusive writes, code-mode execution, child return, cancellation, replay refusal, provider fallback and budget behavior. Ran the four local probes recorded above. The first probe invocation failed because of a module import path; the corrected invocation from `apps/agent` completed successfully.

CodeGraff findings come from its freshly fetched source and documentation; its binary/test suite and live provider behavior were not executed. No head-to-head benchmark, production inspection or paid inference was performed. Broad feature absences are scoped to inspected Aiko code and mounted interfaces. No runtime fixes were made as part of this audit.
