UNLOCK · REVISED UX DIRECTION · PROPOSAL, NOT AN APP REBUILD

A vault, not a dashboard.

NordPass’s familiar login list.
Phantom’s effortless profile switching.
No session management in the interface.

The mental model: “These are my saved logins. These are the ones this agent can use.” Nothing else needs explaining on the main screen.

One main screen

Open directly into saved logins. A prominent profile selector, search, and one primary action: Add login. On desktop, a list beside the selected login’s details. On mobile, the same list opens a full-page detail view with a normal Back action.

The profile dropdown

  • My vault — all logins owned by the user.
  • Build agent, Research agent… — only the logins available to that profile.
  • New profile — name, avatar, choose saved logins, connect the agent.
  • Profile settings live here, not on a separate top-level page.

The name and avatar remain visible everywhere. Switching profiles changes what the owner is viewing; it does not log the owner in as an agent or change permissions.

The login detail

  • Website, username, password with familiar owner-only reveal/copy actions.
  • A simple “Available to” section for agent access.
  • For passwordless accounts, show the recognizable sign-in method, such as “Google,” rather than a fake password field.
  • Normal editing and deletion in an overflow menu.

No cookie fields, refresh recipes, revisions, expiry timers, or “healthy” badges.

Adding access should take seconds

  1. In My vault: Add login → website, username, password → Save. “Sign in with browser” is an alternative for accounts without a password, not a five-way credential-type wizard.
  2. In an agent profile: Add login → choose an existing login or create a new one → Add to Build agent. The target profile is explicit.
  3. One login, many profiles: adding an existing login grants access to the same saved item. It does not duplicate credentials.

“Remove from Build agent” removes only that profile’s access. “Delete login” is a separate vault-wide action and must say who will lose access. Removing access does not promise to invalidate a sign-in already delivered to an agent.

When things work, say nothing

Unlock maintains sign-ins in the background. The user does not start, pause, refresh, or inspect a session.

Notion · Sign in againReconnect 1Password

These appear only when the user genuinely needs to act. Open a private sign-in flow or reconnect the password manager, then return to the login. No maintenance terminology and no technical troubleshooting dashboard in the normal experience.

Remove, rather than rearrange

Remove from primary navigation: Overview, Sessions, Agent profiles, Sources, Activity, Developers. The profile switcher replaces the agent-profile page. Settings holds import/connected password managers and optional developer setup. Detailed diagnostics remain support tooling, not a page every user must understand.

What to borrow from each reference

Phantom: persistent named profile, avatar, quick switching, simple profile creation. Not balances, networks, wallet-address chrome, or a crypto aesthetic.

NordPass: recognizable login rows, search, a conventional detail view, familiar add/edit/reveal/copy actions. Not an enterprise administration console.

Keep the interface calm and readable: light neutral surfaces, a restrained accent, service icons for recognition, larger everyday text, and comfortable controls. The profile avatar is the distinguishing feature; everything else should feel ordinary.

What stays underneath

The existing SDK, access assignments and session-handling boundaries can remain. The redesign changes what the user has to think about—not the underlying security model. The current prototype still uses synthetic data only; real credential storage, provider login and unattended maintenance are not implemented.

UI/UX Pro Max’s verified Password Manager guidance explicitly recommends a vault-focused interface, not a dashboard. Its generic design-system search returned a marketing layout, which was rejected. Progressive-disclosure and navigation guidance came from the skill’s quick reference after targeted searches returned unrelated matches. Phantom and NordPass are pattern references here, not claims of a fresh live-product audit.
