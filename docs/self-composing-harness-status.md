### Verifier registration protocol (engineering tooling, not a runtime API)

The manifest starts with an empty `verifiers` object and null verifier bindings. Register a verifier only after independent review confirms that it actually executes the named product path and checks the full residual, including negative/restart cases; generated implementation tests cannot approve themselves. The review boundary includes this gate, the fixed requirements, expected assertions, fixture bytes and verifier code. A review identity string is audit metadata, not cryptographic proof of reviewer independence.

Each `verifiers[id]` records:

- `entry`: repository-relative Bun TypeScript entrypoint; `entrySha256`: exact entry bytes.
- `inputDigests`: repository-relative SHA-256 pins for the exercised implementation and independently controlled fixtures/tests. Include imported verifier helpers, configuration and the transitive implementation/dependency lock closure; the gate checks listed pins before and after execution. The reviewer is responsible for complete dependency coverage; a hash does not establish semantic correctness.
- `runtimeSha256`: the exact Bun executable; `dependencyTrees`: complete installed package tree digests including path inventories; `graphEntrypoints`: reviewed roots whose resolved source inputs must all be pinned. The gate checks them before and after runtime execution.
- `review: { identity, rationale }`, describing independent acceptance of the verifier and its scope.
- `timeoutMs`: a positive integer no greater than 60000. Use bounded witnesses; do not hold the gate on an endless model/provider loop.
- `checks`: exact check IDs, each with `nativeTrace` (a retained evidence filename) and nonempty fixed `assertions`. Each assertion has a unique `id`, fixed evidence `artifact`, JSON `pointer` and `expected` value. Use semantic postconditions and actual negative/recovery outcomes, not file-existence, a model answer or a success flag alone.

Set each applicable check's `verifier` to that registration ID. The runner executes the pinned entry with `--report <private-temp-path> --nonce <fresh-random-value>` from the repository root, `TMPDIR=/tmp`, and `SELF_COMPOSING_EVIDENCE_DIR` naming its private run directory. Only PATH and these execution settings are passed through; Bun is launched with `--no-env-file` so repository `.env` files are not automatically loaded and provider secrets are not inherited. A verifier can invoke actual local fixture methods and capture native events using the inspected package APIs. The runner uses Bun directly without a shell and does not deploy or create subscriptions itself. Verifiers are reviewed trusted programs, not sandboxed untrusted candidates; their own fixture/transport boundary must enforce the no-external-effects scope.

The report must be JSON with `schemaVersion: 1`, the supplied `nonce`, `checks[id]: { status: "satisfied", operationId, traceRef }`, and `artifacts: { relativePath: sha256 }`. Write artifacts next to the report. A pinned assertion's artifact contains the observation at its registered JSON pointer; the gate compares that value against the separately registered expected result, checks the artifact digest, and requires retained nonempty native trace evidence. Native trace interpretation belongs to the independent verifier because installed Tardigrade versions differ. `traceRef` must equal the registered native trace artifact path. Additional event-log references or real Voyager URLs may be included when actually produced, never invented.

The runner rejects escaped paths/symlinks, oversized/empty evidence, changed pins, wrong nonce, missing/unknown witnesses and failed fixed assertions. Zero process exit alone does not pass. Run evidence is retained in `/tmp/unlock-self-composing-evidence-*` and its path appears in the report; archive it under approved retention before relying on it as long-lived attestation. Temporary evidence is not a durable production registry. The gate does not accept historical JSON receipts as fresh execution: the current reviewed entry must run and emit its new nonce.

The gate cannot prove that a dishonest trusted verifier observed real effects merely by parsing its output. Independent review, controlled fixtures, raw native traces and protected verifier/fixture registration are essential. There is deliberately no automatic promotion from arbitrary test names, hand-edited statuses, files existing, old smoke artifacts, or claimed Contract satisfaction.
