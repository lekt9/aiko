# PLAN — The Unbrowse Commons as an On-Chain Skill Ledger

> Status tags follow house convention: **BUILT+PROVEN / DESIGNED / RESEARCH-DIRECTION**.
> Companions: `contract/docs/PLAN-contracts-as-onchain-ebm-weights.md` (energy +
> weights), `contract/docs/ECONOMICS-cooperative-commons.md` (reward economics),
> `contract/docs/03-ONCHAIN-privacy-solana.md` (chain + privacy),
> `neuron/AGENTS.md` (skill admission, outbox settlement).

**Goal (Lewis's words):** merge Unbrowse with Aiko; move the Unbrowse commons
on-chain as a ledger; use ERC-8004 for reputation; use energy-route ranking to
rank skills generated by Unbrowse users; each Unbrowse client is an agent with
accountability to the ledger.

## The one decision that gates everything: which chain

This is the load-bearing conflict in the plan as stated, and it should be
settled before any code.

- **Contract's on-chain stack is Solana.** `iq_ledger` anchors claim hashes to a
  deployed Solana program; `solana_rpc` is devnet-proven; `voltr.zig` holds a
  real mainnet FDRY vault; the rent model is *measured* (32 B = 0.001 SOL, 1 KB
  = 0.008 SOL, 4 KB = 0.029 SOL) and sets the ≤4 KB on-chain boundary.
  **BUILT+PROVEN.**
- **ERC-8004 is EVM.** It went live on Ethereum mainnet 2026-01-29, with
  reference deployments on Base Sepolia, Linea Sepolia, and Hedera Testnet. Its
  three registries are Identity (ERC-721, agent ID `eip155:<chain>:<addr>`),
  Reputation (`giveFeedback()` → `NewFeedback`/`FeedbackRevoked`), and
  Validation (`validationRequest()` → `validationResponse()` with a 0–100 score
  plus evidence URIs). It is chain-agnostic in spirit but specified for EVM.

**Recommendation: dual-chain, and do not port the Solana work.**

| Layer | Chain | Why |
|---|---|---|
| Skill bytes, EBM centroids, CAS blobs, commitments | **Solana** | Already built + rent-measured; this is the high-volume write path |
| Agent identity, reputation feedback, validation scores | **Base (EVM)** | ERC-8004 is the *interop* surface — its whole value is agents outside your system reading it |

The two compose without a bridge: ERC-8004's Reputation Registry already stores
feedback as small on-chain records pointing at off-chain JSON, and the
Validation Registry takes **evidence URIs**. A Solana commitment hash *is* a
valid evidence URI. You publish reputation where the ecosystem reads it, and
keep the heavy ledger where you already measured it to be affordable.

Rejected alternatives: **all-EVM** discards `iq_ledger`/`voltr`/the measured
rent model for no interop gain on the data path. **Solana-only with
ERC-8004-shaped registries** gets the schema without the network — and the
network is the entire reason to adopt a standard.

## What already exists (do not rebuild)

The plan is mostly *wiring*, not invention. Honest inventory:

- **Energy router — BUILT + benchmarked.** `contract recommend "<goal>"` returns
  the argmin-energy binary plus the nearest PROVEN command. Trains a per-binary
  prototype purely from ledger verdicts (satisfied → +1, died → −1); no
  hardcoded lexicon, no cold-start seed. Embeds with bge-small-en-v1.5 as a
  pure-Zig 12-layer BERT over int8 weights. Measured **88.9%** on 54 goals × 6
  binaries leave-one-out (random 16.7%, keyword 1.9%, Qwen3-0.6B 96.3% at 20×
  the bundle). `energy_router.zig` also exists in Neuron as a limb.
- **Energy function — BUILT.** `firingEnergy(g_ok, conf, cost, settle, viol)`:
  grounding failure +3.0, confidence shortfall, cost×2, settlement distance,
  violations×2.5. Already the right shape for ranking skills.
- **CAS + free dedup — BUILT+PROVEN.** `cas.zig`; content-addressed PDA means
  identical content = same account = write-if-absent.
- **Skill admission — BUILT.** Neuron admits skills with digest, signature,
  scan, tests, and **no ambient authority**.
- **Consequential-effect settlement — BUILT.** Outbox record first, boundary
  crossed only on dispatch, settles only after external state is independently
  read back and compared by content digest.
- **Checked tasks — BUILT.** Every contract task carries a real `--check`
  shell command that exits 0 on success. *This is already the proof-carrying
  primitive the whole reputation design needs.*
- **Cooperative commons economics — BUILT+PROVEN locally.** Usage → USDC to used
  + verified maintainers; reward-not-slash; nothing burned; FDRY as stake.

## The honest wall: a global energy router is adversarially trainable

**This is the hardest problem in the plan and it has no built solution.**

Today the energy router is trustworthy *because the ledger is yours*. A
satisfied verdict is evidence because you produced it. The moment skills are
ranked across all Unbrowse users, the training signal becomes an attack
surface: a skill author who can emit `satisfied` verdicts can promote their own
skill to argmin-energy for everyone. Sybil clients are cheap. ERC-8004
reputation **does not fix this** — `giveFeedback()` is indexed by client
address, and addresses are free.

Do not ship a global router that trains on unauthenticated verdicts.

**The mitigation is already in the substrate — proof-carrying verdicts:**

1. A published skill **must** carry its `--check` command (contract already
   requires one).
2. A verdict only enters global training if an **independent validator** re-ran
   that check and published a `validationResponse()` score to the ERC-8004
   Validation Registry, with the Solana evidence commitment as its evidence URI.
   This is exactly Neuron's "independent second invocation" rule, lifted to the
   network.
3. Feedback weight is **stake-scaled** (FDRY), so promoting a skill costs
   capital proportional to the influence bought.
4. Keep the **fairness floor** from the weights plan: energy *prioritizes*,
   never *forbids*; bounded exploration fraction fires off-prior; HOLD stays
   non-terminal. Mutation-test it (disable → a skill starves → RED).

Unvalidated verdicts still train the **local** prior. Only validated ones train
the **global** one. That split is the whole design.

## The second wall: captured routes are not automatically publishable

Unbrowse skills are learned from real browsing of third-party sites. A raw
captured route can embed session cookies, bearer tokens, account identifiers,
and PII, and it describes a private API the site owner did not publish. Moving
the commons on-chain makes every one of those **permanent and public**.

Gate before any publish path ships: deterministic sanitization (credential and
PII strip) + a redaction witness that fails closed, reusing the sealed-data /
receptor-grant boundary in `capability.zig`. A skill that cannot be proven
sanitized does not get a commitment. This is a gate, not a blocker — but it
must precede Phase 3, not follow it.

## Phases — prove value before paying for storage

The Phase-1-gate discipline from the weights plan applies unchanged: **if the
router doesn't beat baseline on skills, no on-chain storage follows.**

### Phase 0 — Define the skill candidate (no chain code)
Generalize the energy router's candidate from *binary* to *skill*. A skill
becomes a `Candidate` with `grounding_ok`, `evidence_conf_milli`,
`normalized_cost`, `settlement_distance`, `violations` — all of which an
Unbrowse route already produces (cache hit latency → cost, replay success →
grounding, route drift → violations).
**Gate:** written skill→Candidate mapping; a baselined task set of real
Unbrowse tasks; measured current route-selection quality to beat.

### Phase 1 — Energy-rank skills, LOCAL only
Wire skill candidates into `contract recommend`. Train from the local ledger.
**Gate:** energy-ranked skill selection beats current route selection on ≥1 real
metric (task success ↑ / fires-to-settle ↓ / latency ↓) by a stated margin, with
the fairness floor mutation-tested. **If it does not beat baseline, STOP.**

### Phase 2 — Client identity: each Unbrowse client is an agent
Register each client in the ERC-8004 Identity Registry (ERC-721 on Base); the
token owner is the client owner, with operator delegation for the daemon. Sign
every published skill and every verdict with the device Ed25519 identity Neuron's
installer already creates.
**Gate:** a client registers, publishes a signed skill, and a third party
resolves `eip155:8453:<addr>` → agent card → skill commitment. Unsigned or
identity-mismatched skills fail closed.

### Phase 3 — Skill commitments on Solana (after the sanitization gate)
Content-addressed skill blobs; PDA = derive(hash) → free dedup. Skills ≤4 KB
on-chain; larger = 32-byte commitment + off-chain body.
**Gate:** publish a skill twice = 0 new on-chain bytes; evict local, read back
from chain = identical; corrupt a chunk → hash mismatch caught; unsanitized
skill → publish refused.

### Phase 4 — Validation Registry as the reputation gate
Independent validators re-run a skill's `--check` and publish 0–100 via
`validationResponse()` with the Solana commitment as evidence URI. Only
validated verdicts train the global prior.
**Gate:** a skill with a passing independent validation gains global energy
rank; the *same* skill with only self-issued feedback gains none; a sybil
promotion attempt is measured and shown ineffective.

### Phase 5 — Reputation feedback + reward routing
`giveFeedback()` on real usage; route USDC to used + verified skill authors per
the existing reward-not-slash economics.
**Gate:** usage → payout reconciles against the ledger; forfeit → honest;
nothing burned.

### Phase 6 — Frecency cache (chain canonical, local hot)
Hot skills full local, cold = commitment-only, rehydrated on use.
**Gate:** `rm -rf cache && refetch → identical`; cold miss + no network → HOLD,
never fabricate.

## Cross-cutting invariants

- **Prove value before paying for storage.** Phase 1 is the fork.
- **Only independently-validated verdicts train the global prior.** Local
  verdicts train the local prior only.
- **Fairness floor:** energy prioritizes, never starves. Mutation-tested.
- **Chain canonical, local reconstructable:** every phase survives
  `rm -rf cache && refetch → identical`.
- **Agency spend-gate first** (`agency.zig`): every on-chain write checks budget
  before signing, or a publish loop drains the wallet.
- **Honest naming.** Say "centroid", "linear", "encrypted", "commitment" — not
  "zk". There is still no production ZK system, and query privacy over a shared
  index remains **UNSOLVED**: your data at rest is private, your *attention* is
  not.

## Build spine

`0 skill candidate` → `1 energy-rank locally (PROVE)` → *fork: worth it?* →
`2 client identity` → *sanitization gate* → `3 skill commitments` →
`4 validation` → `5 reputation + reward` → `6 frecency`.
